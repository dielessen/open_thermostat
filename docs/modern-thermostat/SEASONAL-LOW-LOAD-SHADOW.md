## Source contract and priorities

Profile defaultdisabled; enabled AND source-qualified installation, bounded sensor TTL1..120s and loop gap1..300s required. Optional explicitly reviewed frost target5..15C. These are SHADOW review facts, not physical protection. Caller must provide genuinely admitted fresh source provenance/sensorAt, monotone nonzero owner generation from the existing session owner, actual independent safety/DHW facts and explicit mode choices. Cache polls/heartbeats do not change sensorAt. No clock fallback, guessed temperature or extrapolation.

1. Invalid profile, reversed/gapped loop time, missing lease/preemption and fenced/old generation cannot request heat. A gap fences even a newly arriving owner; valid greater-generation recovery still needs the existing hydraulic fault-clear/readiness path.
2. Stop/all-off, unknown/unsafe limits and active or unknown DHW suppress demand before any pulse minimum or rate budget. Boiler/actuator/limit faults remain independently authoritative in the supervisor, never weakened by frost.
3. Missing, unqualified, future, expired or implausible room observation blocks all modes. HA-dependent rooms therefore have NO generic freeze protection when HA/source/lease is lost. frostProtectionAvailable remains false, even when advice is selected.
4. Explicit reviewed frost choice can override summer target inhibition, but nothing above it. It substitutes only a bounded room target into the existing regulator; it does not start a pump, assert flow or fabricate a safe valve position. Without that explicit choice summer produces no demand, even if cold. No outdoor-cache automatic frost trigger.
5. Normal low-load advice reuses existing hysteresis/localTRV/directPI/slowBinaryPI profiles. Slow binary PI suppresses too-short requested pulses instead of rounding up to an unsolicited minimum; fresh boot/new owner restarts conservative min-off. Stop/DHW/summer/unknown sensor beats min-on immediately; no integral backlog while unusable. Existing WaterWriteBudget consumes an immediate null-target withdrawal despite cadence/slew limits. No heat solely to keep a minimum water target.

Changing owner generation withdraws the old zone demand for at least one evaluation and maps to the existing adapter-loss withdrawal/fault behavior. Fresh-looking feedback for the OLD opening command never qualifies a new owner. Existing verified fault clear, bounded prior-path retention and a NEW opening/feedback/flow sequence are still necessary. Native candidate review found and reproduced this carryover gap before it was closed; the initial probe is retained as candidate-only evidence, not misrepresented as an installed regression.

## Withdrawal is not a universal safe physical position

Seasonal restrictions can only remove input permissions; they cannot upgrade an external false demand/source/lease/limit/readiness/flow or supply a missing water target. The same supervisor decides existing-path/postrun using the exact caller-reviewed cause table. A normal summer/stop uses normalStop policy, not an invented source failure. Sensor loss uses sourceLost; lease/preemption/owner transition adapterLost; unknown safety and DHW use their explicit policies. Simultaneous restrictions retain the most restrictive existing policy; deadlines are not refreshed by repeated mode changes. Timing-fault retention is anchored to the LAST known hydraulic tick, never a late callback, so a long gap cannot start a new late postrun. No cold start of a pump/path from a fault. Every physicalOutputsEnabled flag remains false. OpenPathIntent=false is not a physical CLOSE command; retention intent is not measured hydraulic safety.
