# GitHub update checks

`test/test_native/test_github_update.cpp` exercises production release/URL/budget
policy and the actual `VerifiedOta` commit gate. Native SHA/flash/boot boundaries
are explicit fakes: selection is forbidden before every gate. Run via the normal
`pio test -e native`. Run native tests BEFORE firmware builds in this checkout.

`browser.cjs` executes the shipped update page in Chromium with simulated HTTP.
No automatic check/install occurs; explicit selection, cancellation, byte
progress, checksum failure, interrupted response, restart rejection, reconnect
version and previous-image confirmation are covered.

`image_check.cpp` drives the same production gate with the actual packaged app
and independently computed OpenSSL SHA256. Success, modified data, truncation,
flash-readback corruption and mismatched embedded UI metadata are covered:

    g++ -std=c++20 -Isrc -I.pio/libdeps/native/cJSON test/updates/image_check.cpp .pio/libdeps/native/cJSON/cJSON.c -l:libcrypto.so.3 -o /tmp/ota-image-check
    /tmp/ota-image-check out/e32v2/e32v2-update.json out/e32v2/firmware.bin

Public HTTPS roots can be regenerated byte-for-byte with the pinned official
Espressif tool; see certs/README.md. Live TLS validation uses those exact roots.

These tests do not simulate the real ESP32 TLS heap, HTTP driver, flash erase,
power loss, bootloader or physical settings retention. Mandatory board check:
record config -> non-erasing bootstrap -> check/install from GitHub -> reboot ->
version/UI/config readback; interrupt downloads, reject bad images and verify
previous VALID-slot/USB recovery. No production heating/HA action in these tests.
